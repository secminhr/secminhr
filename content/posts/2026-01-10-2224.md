最近在讀 A Syntactic Approach to Type Soundness (A.K. Wright and M. Felleisen., 1994) 時，他們的文章中使用 reduction semantics 來描述語意。因為我對這套使用 context 的描述法不熟，所以在這裡想要記錄一下。

# Syntax
他們使用的語言 syntax 如下：
$$
e ::= v\ |\ e_1 e_2\ |\ \text{let } x \text{ be } e_1 \text{ in } e_2\ \ \ \ \text{(Expressions)}\\
v ::= c\ |\ x\ |\ \text{Y}\ |\ \lambda x.e\ \ \ \ \text{(Values)}
$$

其中 $c$ 是一些額外定義的 constant （$c \in Const$），$x$ 是變數（$x \in Var$），$\text{Y}$ 是弄出 recursion 用的 fixpoint combinator。

# Semantics
他們首先定義了 $\to$ relation 來表示某一個單位的單步 reduction。

```typst
#set page(width: 50em, height: auto, margin: 5pt)
#show math.equation: set text(size: 15pt, weight: "semibold")
#import "@preview/intextual:0.1.1": *

// intertext-rule show rule is required for elements to display properly.
#show: intertext-rule

$
c space v arrow delta(c, v) #tag[($delta$)]\
(lambda x.e) v arrow e[x arrow.r.bar v] #tag[($beta_v$)] \
"let" x "be" v "in" e arrow e[x arrow.r.bar v] #tag[(let)] \
"Y"v arrow v(lambda x. ("Y" v) x) #tag[(Y)]
$
```

$\delta(c, v)$ 只是為了處理 $c$ 那些額外定義的常數用的 <br>
（$\delta : Const \times ClosedVal \to ClosedVal$， ClosedVal 表示沒有 free variable 的 value）

接下來，他定義 $\twoheadrightarrow$。
```typst
#set page(width: auto, height: 100pt, margin: 5pt)

#import "@preview/curryst:0.6.0": rule, prooftree, rule-set
#show math.equation: set text(size: 15pt, weight: "semibold")
$prooftree(
    rule(name: (arrow), e_1 arrow e_2, e_1 arrow.r.twohead e_2)
)$ #h(1cm)
$prooftree(
    rule(name: ("refl"), e_1 arrow.r.twohead e_1)
)$
#v(1cm)
$prooftree(
    rule(name: ("trans"), e_1 arrow.r.twohead e_2, e_2 arrow.r.twohead e_3, e_1 arrow.r.twohead e_3)
)$ #h(1cm)
$prooftree(
    rule(name: ("C"), e_1 arrow.r.twohead e_2, C[e_1] arrow.r.twohead C[e_2])
)$
```

C 是用來表示「Context」，就是一個挖了一格空格的 expression，可以在那個空格裡面填 expression。
C 被定義成這樣，基本上就是在各種地方挖洞：
$$
C ::= [\ ]\ |\ C\ e\ |\ e\ C\ |\ \text{let } x \text{ be } C \text{ in } e\ |\ \text{let } x \text{ be } e \text{ in } C\ |\ \lambda x.C
$$
而 $C[e]$ 就是表示用 $e$ 去填 $C$ 裡面的洞。

對我來說，剛開始看到這樣描述 semantics 的方法時，我困惑的地方是這樣只挖一個洞，為什麼能夠透過 $\twoheadrightarrow$ 推出執行結果呢？感覺上不是 expression 填進去之後就沒辦法操作了嗎？
所以在下面，我記錄一個 expression 的 derivation tree，看一下推的過程大概就能知道他怎麼運作的了。

## Preparation
首先我們加入自然數和加法到 Constants 裡面，我們可以比較簡單看到結果： 
$$
\natnums \subseteq Const \\
\\\text{Add} \in Const \\
\{n^+ | n \in \natnums\} \subseteq Const
$$

並且定義相關的 $\delta$：
$$
\delta(Add, n \in \natnums) = n^+ \\
\delta(n^+, m \in \natnums) = (n+m) \in \natnums
$$

## Derivation
在定義完之後，我們來試著推 $\text{let } f \text{ be } (\lambda x. \text{Add } x\ 1) \text{ in } \text{Add } (f 2)\ 3$ 的結果。簡單看起來最後應該變成 6，derivation tree 如下。
$\text{Add}_e$ 是我們額外推出來的 rule，方便我們做加法，另外，我們也用 $\delta \to$, $\beta_v \to$, $\text{let} \to$ 來表示把對應的 reduction 透過 $\to$ rule 轉成 $\twoheadrightarrow$（用了這些輔助工具還是好小，沒招了）：
```typst
#set page(width: auto, height: 150pt, margin: 5pt)

#import "@preview/curryst:0.6.0": rule, prooftree, rule-set
#show math.equation: set text(size: 15pt, weight: "semibold")

$
"Add"_e = #prooftree(
    rule(
        $n in NN$,
        $m in NN$,
        $"Add" n space m arrow.r.twohead (n + m)$
    )
) = #prooftree(
    rule(
        name: [(trans)],
        rule(
            name: [($C = [ space ] space m$)],
            rule(
                name: [($delta arrow$)],
                $n in NN$,
                $"Add" n arrow.r.twohead n^+$
            ),
            $"Add" n space m arrow.r.twohead n^+ space m$
        ),
        rule(
            name: [($delta arrow$)],
            $m in NN$,
            $n^+ space m arrow.r.twohead (n+m)$
        ),
        $"Add" n space m arrow.r.twohead (n+m)$
    )
)
$
```

觀察 derivation tree，可以發現他主要靠 transitivity 來讓多步連在一起。另外 C 能夠讓我們去 extend 一個 expression，或者說，他能夠框定一個 subexpression，使其可以進行 evaluate。
這純粹是看從什麼角度看。如果從上往下看 derivation tree，那麼 C 就是用來 extend 一個 expression，使我們需要 expression 出現。從下往上看的話，那就是 C 能夠選擇 subexpression，讓我們可以對指定 subexpression 做推導。

另外一個值得注意的是，由於 C 的定義，一個 expression 的 derivation tree 未必是唯一的。例如 $\text{Add} (\text{Add } 1\ 2)\ (\text{Add } 3\ 4)$，下面兩個 derivation 都是合法的。
```typst

$
#prooftree(
    rule(
        name: [(trans)],
        rule(
            name: [(trans)],
            rule(
                name: [($C = "Add" ("Add" 1 space 2) space [ space ]$)],
                rule(
                    name: [($"Add"_e$)],
                    rule($3 in NN$),
                    rule($4 in NN$),
                    $"Add" 3 space 4 arrow.r.twohead 7$
                ),
                $"Add" ("Add" 1 space 2) space ("Add" 3 space 4) arrow.r.twohead "Add" ("Add" 1 space 2) space 7$
            ),
            rule(
                name: [($C = [ space ] space 7$)],
                rule(
                    name: [($C = "Add" [ space ]$)],
                    rule(
                        name: [($"Add"_e$)],
                        rule($1 in NN$),
                        rule($2 in NN$),
                        $"Add" 1 space 2 arrow.r.twohead 3$
                    ),
                    $"Add" ("Add" 1 space 2) arrow.r.twohead "Add" 3$
                ),
                $"Add" ("Add" 1 space 2) space 7 arrow.r.twohead "Add" 3 space 7$
            ),
            $"Add" ("Add" 1 space 2) space ("Add" 3 space 4) arrow.r.twohead "Add" 3 space 7$
        ),
        rule(name: [($"Add"_e$)],
            rule($3 in NN$),
            rule($7 in NN$),
            $"Add" 3 space 7 arrow.r.twohead 10$ 
        ),
        $"Add" ("Add" 1 space 2) space ("Add" 3 space 4) arrow.r.twohead 10$
    )
)
$
```
